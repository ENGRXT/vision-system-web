# Contributing

Thank you for considering a contribution.

## Before you start
- Open an issue to discuss substantial changes before implementation.
- Keep changes focused and explain the problem they solve.
- Do not submit secrets, credentials, private infrastructure details, personal
  data, customer data, or material you do not have the right to publish.
- Do not include generated evidence or production data in pull requests.

## Development workflow
1. Fork the repository and create a descriptive branch.
2. Install dependencies using the project development instructions.
3. Add or update tests for behavior changes.
4. Run the relevant test suite and report the exact commands and results.
5. Update documentation when interfaces, configuration, or behavior changes.
6. Open a pull request describing motivation, implementation, validation, and
   any compatibility or security considerations.

## Code quality
- Prefer small, reviewable changes.
- Preserve existing API compatibility unless a breaking change is intentional
  and documented.
- Never hard-code environment-specific addresses or credentials.
- Use environment variables for deployment-specific configuration.

## Security
Do not report vulnerabilities in public issues. Follow SECURITY.md.
